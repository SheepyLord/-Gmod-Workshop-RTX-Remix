# 0107: The Model Hotloader's natives are built on GitHub from a source copy kept here

- Status: Accepted 2026-11-05 (completes [ADR 0106](0106-the-rtx-package-built-on-github.md): no native
  binary of the package comes from `packages/` any more)
- Decided by: the user, asked how the Model Hotloader's four natives should get a source GitHub can
  build (2026-11-05): "Copy the source here".

## Context

ADR 0106 left four binaries of the package taken from `packages/`: the Model Hotloader's
`gmcl_mmdhl_win64.dll`, `gmsv_mmdhl_win64.dll`, `mmdhl_runtime_win64.dll` and `mmdhl_worker.exe`. They
were built on 2026-10-26 from the public commit `ecd7c426` ("Version 2.3.1") of
SheepyLord/Gmod-Model-Hotloader-with-Vulkan plus 41 changes staged, uncommitted, in its author's worktree
`wt-full-textures-props` (the buoyancy and secondary-water work the packaged add-on uses). Every change
there is staged and none unstaged, and no source file is newer than the shipped DLLs: the index is their
source. The add-on checks the natives it finds against its own hash records, `native_policy.lua` (the
installation override this part ships evaluates them by size and SHA-256) and `mmdhl-native-release.json`,
which its `scripts/native_manifest.py` writes from a build.

## Decision

1. **The source is kept here.** `packages/model-hotloader/source/` holds what the native build reads,
   copied from that index with `git cat-file` (`mmdhl/`: CMake, `native/`, `shaders/`, the C++ tests,
   the build's scripts, the dependencies' licences), imported with `tools/inputs.py`, with
   `provenance.json` (each file's size, SHA-256 and git blob; the shipped release record),
   `staged-changes.patch` (the ten copied files that differ from `ecd7c426`) and `Source.md`. The part
   does not ship it. The Lua add-on stays where it was (`mmd_hotloader/`).
2. **GitHub builds them with the add-on's own recipe.** The workflow's `hotloader` job
   (`tools/ci/build_hotloader.ps1`) extracts that tree (`tools/inputs.py extract`), runs its
   `scripts/bootstrap.py` (pinned GitHub archives, CoACD's wheel) and `patch-bullet-threading.py`,
   builds the targets `mmdhl_client`, `mmdhl_server` and `mmdhl_worker` (with `mmd_runtime`) with CMake,
   Visual Studio 2022 x64, Release, and checks that the worker reports release 2.3.1.
3. **The hash records come from the same build.** The add-on's `scripts/native_manifest.py` rewrites the
   2.3.1 entry of a copy of the shipped `native_policy.lua` and writes `native-release.json` from the
   files just built; both replace the part's copies in the package (`build_package.py --built`), so the
   add-on accepts exactly the natives it is shipped with. The report names them as generated by the run.
4. **Nothing is taken from `packages/`.** The workflow's `KEEP_PACKAGED` list is gone; any native
   binary the run does not provide fails it. The job is cached by its sources like the others.

## Consequences

- The natives' build identity is `<this repository's commit>-<UTC configure time>` (the add-on's CMake
  takes `git rev-parse HEAD`), and the policy's 2.3.1 entry changes with every rebuild. Players' copies
  of the earlier 2.3.1 build no longer match it, but the package deploys the natives and the policy
  together, so an installed package always matches itself.
- A change to the add-on's native code reaches the package only through a new copy here (and a
  rebuild), as a part's other inputs do (ADR 0033). When the author commits and pushes these changes,
  the copy can be replaced by a pin of that commit.
- The add-on's MIT licence and its dependencies' licences come with the copy.
