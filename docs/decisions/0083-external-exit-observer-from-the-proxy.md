# 0083: An external exit observer from the proxy DLL

- Status: Accepted 2026-11-01
- Decided by: R7-B implementation under the user's post-crash report request

## Context

The user wants a reason after a crash closes the game, including out-of-memory, fail-fast,
stack-overflow and Remix fatal-exit paths. An in-process exception handler cannot reliably
report those failures. R6 already classifies and retains local evidence at the next start
([0063](0063-local-session-evidence-and-memory-telemetry.md)). The installed bootstrap must
remain one `winmm.dll`; no extra executable can be required.

## Decision

Start System32 `rundll32.exe` at bootstrap startup, after the evidence worker has recorded
the session and copied the previous log, before loading the runtime. Export
`NativeLoaderObserveW` from the same DLL. A DllMain guard recognizes the full System32 host
path and returns before resolving winmm, patching an entry point, deploying or starting workers.
The observer initializes outside loader lock. No extra file is extracted.

Pass an inherited, restricted process handle and ready event using a process attribute
handle allowlist. Validate the exact game executable path, PID, process creation time,
inherited-handle flag and parent PID before acknowledging readiness. No PID-based reopen
is used to wait for the game. Wait for that process handle, then get its exit code. Remix's
own crash/consent prompt therefore finishes before our one OK dialog can appear.

Reuse `evidence::classify`: explicit no-memory/commit-limit statuses are strongest; specific
fatal logs and fresh crash artifacts explain otherwise generic exits. Unknown exceptions
retain their hexadecimal exit code, with access-violation/fail-fast/stack-overflow/C++ labels.
A zero exit, or a deliberate engine quit without fatal evidence, is clean. Fresh fatal
Remix evidence can explain an exit with code zero. Shader debug data alone is not a crash.
For a generic nonzero exit without concrete failure evidence, a sample no older than 30 s
with at most 512 MiB free commit supports a distinct **likely** out-of-memory conclusion.
The latest-only snapshot must match the process token; CSV fallback must fit this session's
time window. A known exception is not replaced by memory inference.

The observer calls the same bounded, sharing-friendly evidence collector and retains an
`exit-report.json` inside its archive. It includes the code, identity, timing, reason, folder
and dialog-suppression flag; the archive receipt covers the report. Add end metadata to the
start marker only if its exact generated bytes still match this session. The next start
reuses that conclusion and archive; clean ends make only an end marker, avoiding normal
starts rotating crash evidence. A per-root named mutex serializes observer collection and
next-start collection. An observer that loses a race to a newer start refuses to read that
new game's evidence. It never overwrites a changed session marker.

Use the seven existing label catalogs. Resolve an explicit `+gmod_language`, then archived
`gmod_language` in `config.cfg`, then Windows locale, with English fallback. Load user32
dynamically after exit, retaining the bootstrap's KERNEL32-only import table.

`NATIVE_LOADER_EXIT_REPORT=quiet` suppresses our window while keeping evidence/JSON;
`off` skips the observer for unrelated synthetic tests. The PoC harness forces `quiet`.
Neither value changes Remix's crash-dump consent. Global loader off switches prevent startup.
The read-only `NativeLoaderExitPreviewW` export shows each localized reason without a game,
an actual crash, fabricated evidence or altered next-session state.

## Consequences

The observer is already alive and has its own stack/address space before a runtime failure.
It consumes one mostly sleeping process per enabled loader session. Startup waits at most
three seconds for readiness; failure is a note, never an activation veto. Evidence collection
remains bounded to five intact archives / 200 MiB and preserves original and edited files.
Nothing is sent or uploaded.

Diagnosis is evidence, not proof of root cause. Disk/permission failures can prevent a saved
report; Windows policy can refuse the observer or UI. Power loss, OS shutdown, a terminated
observer, or failure before it starts cannot guarantee a dialog. Immediate restart can win
the collection race; the old observer then stays silent rather than inspect a different game.
Language changes not archived before a crash may fall back to the last archived language.

## Alternatives considered

- An in-process exception filter cannot survive all the failures being reported and competes
  with the engine/runtime's crash handlers.
- Shipping a second EXE breaks the one-file bootstrap. Extracting one adds executable-file
  ownership, update, antivirus and cleanup problems without improving process isolation.
- Waiting by reopening a PID risks reuse. A broad inherited handle set exposes unrelated
  handles; the explicit allowlist avoids that.
- A next-start-only report is too late for the user's request. Reclassifying independently
  at exit and startup risks contradictory reasons and duplicate evidence.
