## What changed

- Saved actor entries now require successful material/carrier mounts and server
  precaching before publication. The hotloader NPC factory uses the same gate.
  Cached mount success is reused only while archive content and the requested
  carrier model remain visible; stale entries re-mount.
  See [ADR 0090](../decisions/0090-ready-carriers-before-actor-publication.md).
- Saved manual mappings retain priority.
  Legacy mappings keyed only by the former English source name stay active;
  Clear Mapping removes their old key when explicitly requested.
  Automatic expression binding matches
  original PMX identities first, with nanoem-compatible CP932/width/case rules.
  The importer keeps custom VMD names and merges only identical identities.
- When the model lacks a name, the reviewed table uses meaning plus each
  model's moved-vertex geometry. Both-eye fallback requires both eyes. Overflow
  morphs play/reset through the hotloader API, with 32-bit build/debug IDs.
- Assigned Flex/targets show original PMX names; stable controller names remain
  available for overrides. Built v2 and `_fm2` keys rebuild stale caches without
  deleting old files. See [ADR 0089](../decisions/0089-pmx-identities-and-geometry-checked-vmd-expressions.md).

## Corpus evidence

The main checkout's corpus was read in place; scratch/results stayed here.
`tools/mmd_morph_corpus.py` audits 1,225 readable models and samples 48 model
files for displacement similarity. It accepts 62 fallback synonyms after group
and offset corroboration. A unit-weight single child, or complete opposite
pair, can establish equivalence; partial recipes are rejected. Offset evidence
requires cosine >=0.995 and norm ratio 0.95–1.05 on the same panel/side. Three
observations and no conflicting meaning are needed. Costume/copy variants are
observations, not independent authors.

- 笑い: 999 bilateral, 1 left-sided, 9 without geometry, out of 1,009 models.
- EL_Happy_l_CLO / EL_Happy_r_CLO: character-right / character-left respectively
  in all 345 occurrences of each. biyan_L / biyan_R use the other convention.
- The 19 unique labels retained by the user's built cache yield 23,275
  model/label pairs: 15,930 (68.443%) exact name, 234 (1.005%) meaning,
  7,111 (30.552%) unresolved. This is unweighted coverage across every model,
  not a claim that every character supports every expression; the original
  imported motion's dropped/unresolved tracks are absent from a built header.

Full counts, recipes, accepted/rejected and offset evidence are in
`out/r10/corpus-analysis.json`; aggregate fixtures, without models, are committed
as `tools/tests/mmd_morph_statistics.json`. All 1,225 models have at most 476
morphs, well within the overflow adapter's range.

## Native naming recommendations

No native rename is shipped. Preserve presets and offer versioned metadata in
a future native release instead:

- `eye_blink_happy_left/right` and `eye_blink_left/right` describe the usual
  Japanese wink convention, but a minority of models reverse the authored side.
  Supply a measured side separately; do not infer it from these names.
- `EL_Happy_l_CLO` and `_r_` have inverted character sides in this corpus; their
  native ASCII-derived spellings retain that ambiguity.
- Correct the spelling `eyes_sqeeze` only with a saved-preset migration/alias.
  It is はぅ (squeeze), distinct from `eyes_peaceful` (なごみ).
- Recognize the half-width `ｳｨﾝｸ２右` explicitly in a future name catalog; the
  current native table can fall back to a generic `morph_<index>` for it.
  Original-name binding already handles it correctly in this change.
